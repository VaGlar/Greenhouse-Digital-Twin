Greenhouse Digital Twin — internal reference

How the pieces talk to each other

Every simulated hour, real historical weather feeds the climate model, the climate model and crop model hand values back and forth, and the crop model accumulates into a season's yield. Config on the left is what you set once; the loop in the middle runs every hour, with the equation behind each box; the tags are the individually-sourced numbers from docs/assumptions/.

SOURCED — literature/engineering citation, see docs/papers/ PLACEHOLDER — plausible estimate, no specific citation yet SITE-SPECIFIC — real design value for this greenhouse DERIVED / physical constant — computed or a physics fact, not a modeling choice

Weather

twin/weather.py

  • SOActive source is real historical data (10-year average, Αλεξάνδρεια Ημαθίας) via the Open-Meteo API — the old synthetic sine-curve generator is kept only as a fallback
  • PHthe "typical year" averaging blends clear-cold nights with milder cloudy ones, likely understating the coldest real nights

Climate Model

twin/climate_model.py

  • SOCHP heat/CO2 output is fixed (grid-driven) — surplus is dumped/vented, never throttled to demand
  • SOthermal screen and fan-pad cooling are both fully automatic, no manual schedule to get wrong
  • PHcondensation uses an engineering-approximated cover surface temperature, not a measured one

Crop Model

twin/crop_model.py

  • SOcanopy photosynthesis now properly self-shades (Beer-Lambert) and fruit set has its own, narrower temperature sensitivity than photosynthesis
  • PHsenescence/leaf drop still not modeled — biomass never shrinks from aging, only from respiration

API + Frontend

api/main.py, frontend/

  • DEstructural values (area, CHP size) stay backend-only by design — never a per-run slider
  • DEevery run returns a fresh result; no history or scenario comparison stored yet
