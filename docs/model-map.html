Greenhouse Digital Twin — internal reference

How the pieces talk to each other

Every simulated hour, weather feeds the climate model, the climate model and crop model hand values back and forth, and the crop model accumulates into a season's yield. Config on the left is what you set once; the loop in the middle runs every hour; the constants inside each box are the individually-sourced numbers from docs/assumptions/.

SOURCED — literature/engineering citation, see papers/ PLACEHOLDER — plausible estimate, no specific citation yet SITE-SPECIFIC — real design value for this greenhouse DERIVED / physical constant — computed or a physics fact, not a modeling choice

Weather

twin/weather.py

  • PH100% synthetic sine curves — no real historical data yet, the single highest-value future upgrade
  • SSlatitude_deg is stored but unused by the generator

Climate Model

twin/climate_model.py

  • SOCHP heat/CO2 output is fixed (grid-driven) — surplus is dumped/vented, never throttled to demand
  • PHcondensation uses an engineering-approximated cover surface temperature, not a measured one

Crop Model

twin/crop_model.py

  • SOCO2's real yield effect is mostly bigger leaves (LAI), not faster instant photosynthesis — both channels are modeled
  • PHsenescence/leaf drop still not modeled — biomass never shrinks from aging, only from respiration

API + Frontend

api/main.py, frontend/

  • DEstructural values (area, CHP size) stay backend-only by design — never a per-run slider
  • DEevery run returns a fresh result; no history or scenario comparison stored yet
